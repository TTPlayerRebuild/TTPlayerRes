# ttpres 原版基准与扩展资源实现

日期：2026-10-13。源码位置：`ttpres`；对应宿主改动：`rebuild`。

## 1. 原版实际契约

资源 DLL 本身没有可以恢复的播放或界面回调代码。原版 PE 无代码段、入口、导入、导出和 TLS；调用流程位于 `reverse/decompiled/TTPlayer.exe.pseudo.c`：

| 原版入口 | 约束 |
| --- | --- |
| `004566E2 → 004BEBFF` | 在系统加载器之前检查 PE，并将节表后的 16 位字累加、字节重排、取反，与 DOS 头 +0x20 比较 |
| `004C077E CPlayerApp_InitializeResources` | 从 EXE 目录加载 DLL，读取字符串 128；仅认可千千静听、千千靜聽、TTPlayer，然后读取 0x8299 版本文字 |
| `004C08DD CPlayerApp_ShutdownResources` | 最后释放资源模块，所有资源句柄依赖该生命周期 |
| `0041F73F` | `FindResourceW` / `LoadResource` / `LockResource` 读取 ZIP 类型资源 |
| `004A747D CSkinManager_LoadPackageXml` | `<Default_Skin>` 对应内置 ZIP，继续由宿主解析四份皮肤 XML |
| `0045DFBA CPlayerWnd_ShowMainContextMenu` | 载入菜单 138，依占位命令编号加载共享子菜单；后续代码依赖编号与位置 |

原版共有 192 项、语言 0x0804：ZIP 2、CURSOR 2、BITMAP 25、ICON 6、MENU 25、DIALOG 49、STRING 74、GROUP_CURSOR 2、GROUP_ICON 1、VERSION 1、HTML 1、TOOLBAR 4。字符串块含 451 条非空文字；49 个 DIALOGEX 共 677 个控件。

字体不是一律套用现代系统字体：46 个模板为 9pt 宋体，264、265、397 为 8pt MS Shell Dlg。原 weight、charset、控件样式、DLU 和顺序全部保留。

## 2. 基准来源和无损重建

使用主目录原版 DLL，原大小 304,128 字节，SHA-256 见 manifest。`AddIn` 的同名 DLL 是第三方修改版：其产品标题、部分对话框、默认皮肤不同，不能用同版本号判断等价。

基准源码由 `tools/import_original.py` 提取并当场反向编译校验，每项必须字节一致。后续干净构建仅使用仓库内源码：

1. 编译 JSON 菜单、DIALOGEX、字符串、工具栏以及 BMP。
2. 对两个独立皮肤目录分别检查文件清单和内容；未改动时保留原 ZIP 压缩流及元数据。
3. 校验 192 项原资源的哈希，生成 `.res`。
4. RC 编译扩展区；以 `/NOENTRY /NODEFAULTLIB /MACHINE:X86 /SUBSYSTEM:WINDOWS,5.01` 链接。
5. `tools/finalize.py` 在最终 PE 的 DOS 头 +0x20 写入原版自定义校验值。
6. 重新读取最终 PE，审计自定义校验、所有原资源和扩展范围。

这个头部校验是本次实际原版启动验证发现并补齐的兼容性要求。仅验证 LoadLibraryW 和资源字节并不能证明原版能够启动；没有该字段会在加载前被拒绝。算法在原 DLL 上重算为 `FB67B567`，与原字段相同；本次重建成品为 `F97893C5`。它不是 Windows PE CheckSum 或发布者签名。没有修改原版 EXE，也没有关闭原版的检查。

默认皮肤 ZIP 为 75 项（71 BMP + 4 XML）；下载皮肤为 17 项（16 BMP + 1 XML）。过去合并解压得到的 89 个文件不是默认皮肤原始数量，两者有三个同名文件，现已分开保留。

PE 外壳与原版不同，包括节布局及确定性链接元数据；API 可见的 **192 项原版资源数据完全相同**。不宣称整份 DLL 的哈希与原版相同。

## 3. 扩展 ABI 1

最终 207 项资源：192 项基准 + 15 项扩展。

| 扩展 | 编号/名称 | 用途 |
| --- | --- | --- |
| 9 个 DIALOGEX | 4090、4200、4210、4220、4230、5800、5810、5820、5901 | LAME、歌词服务器、错误后缀、更改音量、下载管理、压缩包密码、导入进度、压缩分卷、MusicBrainz |
| 4 个 STRING 块 | 256–259（字符串 4091–4142 中已分配项） | 新视觉效果、封面、歌词服务器、系统关联、音量、均衡器和切换列表文字 |
| RCDATA | `TTPLAYER_RES_ABI` | 16 字节签名、版本 1、能力标志 |
| RCDATA | `TTPLAYER_RES_BUILD` | 项目地址、日期版本、基准 SHA-256、资源数量 |

原版忽略这些额外编号。原版字符串 128、0x8299、VERSION/1 和菜单占位项不改动；构建日期不冒充原版播放器版本。

后续新增菜单、模板或图片使用 60000–65535 区间；字符串使用独立块且不得覆盖原版任何类型/名称组合（包括其它语言变体）。审计允许兼容 ABI 1 的高编号增量资源，旧宿主可以继续下载新资源组件并忽略尚未使用的新增项。

## 4. 重建版宿主接入

- `i18n::ResourceText` 对已声明的 EXE 扩展字符串只读取 DLL；先验证 ABI，再检查资源存在。旧 DLL、缺失条目均返回失败/空值，不回退 EXE。
- WTL 对话框通过已有 `i18n::DialogTemplate` 选择扩展模板，即使当前未启用翻译也返回拥有自己内存的模板副本。
- 逻辑 gettext context 保持 `exe/string/…` 和 `exe/dialog/…`，不因物理资源挪到 DLL 改成 `ttpres/…`。
- 原版模板及插件自己的 HMODULE 不参与重定向，所有原版菜单编号和动态状态仍由原宿主路径处理。
- EXE 不再编译任何扩展模板或字符串，SDK 不再导出 `resources/player.rc`。EXE 保留应用图标、文件关联图标、版本及 manifest。
- `ResourceRuntime` 在创建主窗口前检查资源品牌、ABI、9 个对话框和 48 条已分配文字；缺少 DLL、旧 DLL 或不完整扩展均显示更换完整发行包的提示。
- i18n 在资源解析返回空句柄后立即失败，WTL 普通/模态/属性页创建也明确拒绝缺失扩展；防止空句柄被 Win32 解释为 EXE。
- “切换列表”和均衡器重设的备用标签使用扩展字符串；曲目列表、勾选状态和命令执行仍由播放器更新。
- 没有引入额外 LoadLibrary 搜索：只使用启动时已验证并加载的 EXE 同目录资源模块，不缓存可能卸载的裸句柄。

资源移动不修改皮肤绘制算法、组件命中、窗口吸附、播放引擎或选项页的动态逻辑。内置图片仍走已存在的按需解压缓存，完整内存图片读取和新的 DPI 图标属于后续宿主优化，不能由资源 DLL 单独实现。

## 5. 构建与发行

独立 Action 和本地脚本共用日期版本规则，支持当日 `pN` 递增。资源库不依赖 VC-LTL、YY-Thunks、VC 运行库；这些仍可能是播放器自己的构建依赖。

独立 ZIP：`ttpres-版本号.zip`，仅 DLL 和校验文件。

播放器 Action 默认下载 `TTPlayerRebuild/TTPlayerRes` 最新正式 Release，检查 ZIP 外部/内部 SHA-256、原版 192 项哈希、扩展 ABI、x86、无入口/导入/导出/TLS、子系统 5.01，随后打包到播放器根目录。下载失败或基准不符会明确失败。播放器打包前再次检查实际 DLL、扩展模板结构、48 条必需文字及 EXE 不含备用扩展资源，不只相信旁边的 JSON。

Action 不运行测试；静态契约审计是生成发行组件的必要构建检查。本次不执行远程推送或发布。首次托管构建需要先把独立项目上传到用户指定仓库并发布首个正式版本。

## 7. 取消 DLL 回退（同日追加）

用户要求“dll 不使用回退”后，已移除初版的 EXE 备用方案。第 4 节和上述测试表描述的是修改后的行为。现在重建版以完整 ABI 1 扩展资源为启动条件，不要求 DLL 与 EXE 的日期版本完全相同；兼容的较新组件仍可使用。原版播放器继续读取未改变的基准资源，不受此宿主条件影响。

正常资源库的二进制未改变；宿主的资源读取、WTL 失败路径、启动检查、SDK 导出及打包审计已更新。异常样本仅在私有测试目录中生成，不会进入发行包。新增证据：`rebuild/tests/ttpres_audit_20261013/no-fallback-host.log`、`no-fallback-integration-XP.log`、`no-fallback-integration-Win7.log`、`no-fallback-startup-XP.log`、`no-fallback-startup-Win7.log`。
